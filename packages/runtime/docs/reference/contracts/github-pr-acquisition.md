# Public GitHub PR object acquisition

The host-only `createGithubPrObjectReader` accepts an explicit SHA-1 base tip and head tip with independently verified public target and head repository identities. The `acquireGithubPrObjects` producer admits only an explicit public `github.com/<owner>/<repo>/pull/<number>` URL (optionally its `files` or `changes` view), checks anonymous REST target and fork repository IDs and public state, resolves the current target base branch for an open PR, and checks metadata again after native Git acquisition. A closed unmerged PR refuses; a merged PR uses its verified pinned base SHA only while the public objects remain resolvable. Missing or private forks and base branches refuse. A changing PR never seals a complete snapshot. Neither component performs a model call, checkout, publication or write to the user's repository.

The reader contacts only `https://github.com/<owner>/<repo>.git` with anonymous Git smart-HTTP protocol v2. Discovery must advertise `fetch`, `filter`, `shallow` and SHA-1 object format. Fetch requests contain exact object IDs, `done`, supported filters, and no `thin-pack`, packfile URI, credential or client-provided server URL. Redirects are manual and remain on the fixed repository endpoint. Response body bytes, including packet framing and progress, are admitted into one acquisition budget before application retention. This is not a claim that TLS has not received a crossing chunk.

A private bare repository is created under a host-selected scratch root outside the selected workspace, with an empty template, isolated Git configuration and no alternate object store. Every pack is staged in quarantine after the HTTP budget admits it. A worker thread verifies PACK framing, version, object count, SHA-1 trailer and exact zlib stream boundaries. It charges each declared inflated entry before decompression and each complete object target size, including delta targets, before native Git reconstruction. It checks delta headers but does not implement delta application. Native `git index-pack --stdin --fsck-objects` imports only an admitted pack. Extra `.gitmodules` object IDs emitted for filtered trees are bounded, fetched from the same verified repository, and rehashed as blobs; their contents are never executed. The quarantine file is removed after import. The caller must invoke `dispose()` when finished; any guarded failure also removes the private repository. [Git's `index-pack --fsck-objects` contract](https://git-scm.com/docs/git-index-pack) prints the pack hash and IDs for missing `.gitmodules` blobs, not an ID for every packed object. Its combined output uses the sealed 1 MiB `hostInvoker.gitDefaultOutputMaxBytes` allowance; an unusually large set of missing `.gitmodules` pointers refuses with that named limit before follow-up. The separate `changeSourcesGithub.objectsMax` pack-entry capacity does not guarantee every extreme combination of entries and missing `.gitmodules` pointers fits all budgets. The byte counters bound logical payload and retained response bytes, not exact RSS or allocated blocks.

The reader acquires B and H histories with `tree:0`, resolves all merge bases through local Git, and refuses zero, ambiguous or shallow-incomplete ancestry. A shallow frontier must lie below a verified common M. It fetches M and H tree closure with `blob:none`, validates subtree identity, enumerates the complete raw NUL-delimited M..H manifest and fetches each changed-side regular blob under the same aggregate budgets, including the regular side of a type change. During provisional enumeration, non-add/delete rows plus the larger of add and delete counts are a lower bound on final rows: one rename can pair at most one add and one delete. This prevents a valid rename from consuming two slots while refusing an impossible-to-fit manifest early. Final rename-aware enumeration enforces the actual configured changed-path count and preserves modes, IDs and NUL paths. Binary regular blobs remain exact bytes; symlink and gitlink sides remain explicit limitations and do not trigger traversal or filter execution. Invalid UTF-8 paths, missing objects and bounded-output failures refuse. Each subsequent `cat-file` read is checked for type, length and SHA-1 identity.

The effective limits are `changeSourcesGithub.acquisitionMaxBytes`, `packInflatedMaxBytes`, `objectMaterializedMaxBytes`, `objectsMax`, `historyCommitsMax` and `acquisitionTimeoutMs`, with existing `changeSources.changedFilesMax` and `changeSources.commitsMax` applying to the manifest and proposal history. Host overrides are resolved through the normal limits catalog. Receipts include effective values and observed response, inflated, materialized, entry, history and elapsed counts. At-limit work is admitted; the first crossing unit refuses with the catalog's code, observed value, scope and remediation. A refusal never yields a complete prefix.

The producer passes every regular Markdown/MDX before and after side into `createGithubPrCustody`. This process-local custody keeps separate exact Git blob originals and normalized UTF-8 derivatives, rehashes Git SHA-1 and original SHA-256 identities, and verifies each derivative span against its exact original byte range. Its sealed `ChangeRequestRefV1` and `ChangeSnapshotV1` record stable provider/target/PR identity, verified B/H/M and trees, the complete M..H rename-aware manifest, original side IDs and lengths, source observation references and limitations. The acquired graph, manifest rows and accounting are detached immutable facts before custody accepts them; original byte buffers remain writable so custody can rehash and zero them. UTF-8 Git path spelling is preserved in snapshots and source observations: composed and decomposed names remain distinct, while a normalized safe title is only display text. The released access/citation ledgers and `SourceEvidenceService` bind normalized derivatives and complete valid-UTF-8 original views to the same registered runner source tools, with separate truthful content registrations for each view. The host-only `readOriginal` requires the sealed side, path, target-or-fork repository ID and blob ID and returns a fresh copy; the confined original resolver uses that same live custody and rechecks the sealed identity before each read or citation. Disposing custody zeros retained buffers and makes further reads/ref resolution refuse. Decoding a snapshot alone grants no source access.

`withGithubPrReviewBasis(url, options, consume)` extends that producer within one callback and one bounded private reader. After M..H acquisition, it verifies the complete immutable fork head tree H and materializes every admitted regular H blob into a separately registered, temporary `github-pr-head` `RepositoryWorkspace`; admitted symlinks and submodules remain named non-readable entries, while excluded paths are omitted from the public tracked view. The workspace identity binds the stable target and fork repository IDs, B/H/M, exact base and head trees, the complete verified H entry digest and complete manifest digest. The caller checkout is neither the PR head nor a substitute for it. The ordinary repository inventory is built from this registered H workspace, so an unchanged H document absent from the changed-side manifest remains discoverable and readable. Public PR metadata is rechecked after inventory construction and immediately before callback admission; the scoped acquisition records that final request count. A separately sealed, producer-authenticated descriptor lists documentation candidates in the target B tree, including their modes and object IDs; it grants no B content reads or B inventory authority. B can differ from M. Response and object budgets are cumulative across the earlier acquisition and the additional H/B work; the returned metrics are sampled after that work.

The callback receives the scoped acquisition, H workspace, genuine H inventory, B descriptor and cooperative abort signal and returns only its own result. `assertGithubPrReviewBasis` accepts only the exact producer-minted basis while that callback is live; structural copies and retained bases refuse. Only a genuine callback acquisition can mint source custody during that callback; its membership is revoked on exit even with no source sides or an empty H tree. Custody already minted inside the callback retains its separate copied bytes until the consumer disposes it. A returned workspace cannot admit later reads or leases. A live lease at callback exit causes the named `github-pr-workspace-lease-unsettled` failure: the workspace files remain until that lease is released, while the private Git reader is cleaned independently. The acquisition deadline and external cancellation remain active through the final H filesystem settlement, verification and callback admission; the acquisition deadline ends when the callback starts, while its external abort signal remains cooperative. A local filesystem mutation such as scratch creation is awaited before its stall/deadline check, so an operation that never settles cannot be force-canceled; a late return is refused before callback admission and then cleaned up. Final read-only workspace metadata checks use a timed wait. A cooperative callback abort waits for the callback to settle; a consumer throw does not leave the reader or workspace available. If callback or inventory construction fails and workspace closure also fails, both failures remain attached while private-reader cleanup is still attempted. Immediate and lease-deferred H removal share one retained outcome, so a repeated close or direct dispose waits for completion or reports the same cleanup failure; a failed export also retains its original cause when scratch removal fails. This supplier API does not invoke the #885 CLI workflow, persist a saved review, or grant a model B-byte citations.

For a combined PR and explicit H source selection, the callback may call `createGithubPrCustody(acquisition, context, { basis, acquireHSourceObservations })`. The third argument is valid only for the same live basis and acquisition. The provider callback receives custody's one external-input capture and the exact H workspace and run, request, repository, policy and signal context. It returns sealed source observations, an H read scope, the matching producer scope and private resolution/receipt handlers; it cannot return an independent binding or runner service. Before sealing, custody checks each selected path against the registered H workspace's tracked regular entry and current Git blob identity, rereads the exact bytes, checks both original and derivative representations and their external-input registrations, and refuses duplicate identities or mismatched context. It rechecks the live callback basis after each awaited H verification and immediately before sealing. Extra derivative representations may share the one registered input only when their byte digest and length match its primary content; a different-byte derivative refuses before custody is returned. Custody that was sealed while the callback basis was live retains copied bytes and its own disposal lifetime after callback return. It then seals one source binding/reference and one source service over PR changed sides and the selected unchanged H files, with access and citation receipts in the same ledger. The immutable PR diff manifest still contains only M..H changes. The two-argument custody call retains its prior serialized records and behavior. This supplier does not implement the #885 CLI caller or its request projection; the combined installed CLI journey requires that separate consumer release.

The complete manifest retains added, deleted, renamed, binary, symlink and gitlink rows; missing add/delete sides are absent, while zero-byte or blank-only Markdown sides retain original identity and carry `empty-extraction`. Invalid UTF-8 and unsupported modes/media have explicit `unsupported-content` limitations. A source larger than the extractor's derivative/span ceiling retains its exact original and records `partial-extraction`; the derivative is never described as complete. The existing 256-observation binding cap is checked before sealing: 256 real sides admit, 258 refuse. The host retains no prefix on failure.

Tests use real local `git upload-pack --stateless-rpc` output wrapped in an HTTP fixture and actual native index-pack/cat-file. They exercise a diverged base and head, NUL manifest cases, pack deltas, missing external delta bases, interruption, and malformed or over-budget transports without public network access. On Apple Git 2.50.1, the offline representative fork fixture changed 64 Markdown files with 40–64 KiB on each side, retained a rename and deletion, and had 263 acquired history commits. It admitted 2,965,576 response bytes, 7,259,109 inflated entry bytes, 7,347,789 materialized target bytes, and 669 entries, with 20,620 ms of measured reader time, all below the defaults. A further producer/custody fixture retains both sides of all 64 document changes under the same defaults; a single source-reading step at its 262,144-byte ceiling reads only a subset and records the rest as unread or partial. This is acquisition capacity, not a claim that a model considered every document. A separate small actual `WorkflowRunner`/`PiHarness` case uses the materialized target-base checkout and the separately acquired PR head to list and read its derivatives through registered source tools in the read-only review path; a write-mode case exercises registered read and citation tools and a workspace-only reviewable patch. The existing repository workspace materializer rejects a decomposed path in a PR-head checkout during preflight; DocsFab issue #2552 owns that separate checkout limitation. The source acquisition and tool-read proof does not claim that checkout path works. The test provider is offline; no live model or GitHub publication is invoked.

This delivery handles public github.com SHA-1 repositories with registered Markdown/MDX source extraction. A derivative `docsfab_read_source` result remains normalized and can omit the UTF-8 BOM, CRLF separators and blank lines. A separately labeled `exact-original-utf8` result returns readable text fragments whose byte offsets and UTF-8 encoding reconstruct the exact before or after Git blob, including a zero-byte witness. The same confined reader and citation tool bind those fragments to the original registration and external-input receipts; raw reads spend their actual serialized result bytes and refuse before a receipt if credential screening, the live tool output cap, or the shared step budget fails. Invalid UTF-8 and unsupported modes stay named limitations, not fabricated text. The small offline native Git fixture proves actual registered Pi reads and citations for both sides, blank/newline-only, empty and deleted cases. It does not claim that one step reads the 64-document acquisition fixture whole. GHES, private credentials, SHA-256, other source formats, CLI `--pr` intake and a PR review report are outside this boundary. Issue #884 remains open until its remaining acceptance is reviewed; this slice advances it.
