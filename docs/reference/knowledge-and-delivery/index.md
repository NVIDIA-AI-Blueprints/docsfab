This section of the DocsFab reference separates evidence records from
delivery channels. Knowledge contracts define what DocsFab retains and
synthesizes. Delivery contracts define how reviewable results, documentation
previews, and freshness evidence move without granting publication or merge
authority. For more information, refer to [Overview of
DocsFab](../../about/index.md).

## Choose a Reference Area

The following table maps each question to its reference area.

| Question | Area | What it does not cover |
| --- | --- | --- |
| Which command or canonical record preserves product evidence? | [Knowledge Contracts in DocsFab](knowledge/index.md) | GitLab communication, Fern delivery, and publication. |
| How does a completed result reach reviewers or stay current? | [Delivery Contracts in DocsFab](delivery/index.md) | Source acquisition, claim synthesis, and model-record shape. |

## Follow the Evidence Flow

1. Register evidence in a [source thread](knowledge/source-thread-registry.md).
2. Reconcile evidence into an immutable [reference-model package](knowledge/reference-model-package.md).
3. Check whether documentation and retained review evidence [remain current](delivery/documentation-convergence.md).
4. Deliver a review signal through the [GitLab mailbox](delivery/gitlab-host-notification.md) or preview documentation through [Fern site delivery](delivery/documentation-delivery.md).
