Use this retained evaluation record to distinguish deterministic fixture coverage from installed named-workflow qualification.

This page records the DocsFab source-coverage-v1 qualification matrix for
five documentation configurations: plain Markdown, MkDocs, Docusaurus,
Sphinx, and Fern. Each configuration is crossed with the named
`create-documentation`, `update-documentation`, and `review-documentation`
jobs. The matrix is evidence, not a quality threshold, release gate, or extra
workflow entry point. For more information, refer to [DocsFab Knowledge and
Delivery Reference](../../reference/knowledge-and-delivery/index.md).

Run those jobs with the procedures in
[Run a Documentation Workflow in DocsFab](../../workflows/run-a-documentation-workflow.md).
This page does not replace that guide.

## What the Matrix Establishes

A **deterministic fixture-only** cell proves that the sealed corpus,
collector, writer and validator receipts, preserved facts and routes, and
named negative controls fail closed. It does not prove an installed
`docsfab run` job.

An **installed** cell requires a real named-workflow run against a
materialized candidate, with retained package, CLI, workflow, model, profile,
and quality-pack identities, plus access and citation ledgers. Fixture-only,
admission-only, and empty-model records cannot satisfy that cell.

A **pending** cell names the exact missing grant or toolchain. It is not a
pass.

## Collector Commands

From the repository root, collect the deterministic cases and the installed
matrix identified by `v1`. This identifier versions the qualification matrix,
not the DocsFab release:

```bash
node packages/runtime/scripts/source-coverage-qualification.mjs \
  --mode deterministic \
  --corpus packages/quality/benchmarks/runtime/evaluation/source-coverage-v1
node packages/runtime/scripts/source-coverage-qualification.mjs \
  --mode installed --matrix v1 \
  --corpus packages/quality/benchmarks/runtime/evaluation/source-coverage-v1 \
  --output "${TMPDIR:-/tmp}/docsfab-source-coverage-v1"
git diff --check
```

Installed live execution still requires an absolute CLI outside this
checkout, an absolute work root, and
`--acknowledge-installed-execution source-coverage-v1-installed-execution`.
That acknowledgment records operator intent. It does not mint model
credentials, host authority, or a release.

Checked-in receipts live under the source-coverage-v1 `qualification/`
directory. They follow the private-v1 campaign pattern: a campaign
index, retained report identities, and explicit pending or failed cells.

Choose a fresh, real directory for `--output`. The collector refuses a
symlinked output directory and refuses to replace an existing `report.json`.
These checks preserve an earlier report and prevent concurrent collectors from
clobbering each other's output.

## How to Read a Cell

Use this order when you interpret a later receipt:

1. Confirm the corpus id `source-coverage-v1` and the recorded manifest
   digest.
2. Confirm the repository identity. In the historical receipts,
   `testedRevision` is the observed worktree HEAD and is only a base revision.
   A new receipt has exact revision attribution only when `testedRevision` is
   non-null and `testedWorktreeDirty` is `false`.
3. Treat `evidenceStatus: fixture-only` as collector proof only.
4. Treat `status: pending` as an incomplete installed claim.
5. Treat `installedQualified: true` only when every primary cell has
   `status: passed` and `evidenceStatus: installed`.

Do not promote this matrix to a release record, quality score, or extra
`docsfab` entry point.

## Source Acquisition Proof

Offline doctor does not acquire sources and does not call a model. A
`context-v1-source-acquisition` collection distinguishes **deterministic**
fixture producers from **live provider** evidence collected through the
installed CLI. Fixture results cannot stand in for an installed proof. Today
that installed-CLI coverage is partial: only the local provider's `run` and
`do` cells (PDF, DOCX) actually collect live evidence through the installed
CLI; the local provider's HTML `live-agent` cell is not invoked (the
installed live-agent requires an attached interactive terminal, which this
collector does not allocate) and stays `pending`, as do the GitLab, HTTPS,
and Brave live cells, in the collection's own report until their providers
are wired (#1062 N7). `/sources search` remains `search-unavailable` until a
live searcher is wired; GitLab discovery beyond the first page uses the
shipped sources commands, not search.
