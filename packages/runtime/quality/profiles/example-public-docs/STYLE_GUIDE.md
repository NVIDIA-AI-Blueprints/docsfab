# Example public documentation style

- Address the reader directly as “you.”
- Use active voice and present tense.
- Lead with the user outcome, then provide required context.
- Use sentence-style capitalization for headings.
- Use numbered steps only for ordered procedures.
- Put commands, code, parameters, and literal values in code formatting.
- State expected results after the action that produces them.
- Do not use promotional claims, unsupported superlatives, or internal project names.
- Prefer concise paragraphs and specific nouns over ambiguous pronouns.
